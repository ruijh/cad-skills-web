CAD × AGENT 图鉴

把 CAD 交给 Agent 之前，
先挑对那条路线。

收录 GitHub 上能让 AI Agent 真正干活的 CAD 项目：MCP server、SKILL.md 技能包、以及自带 MCP 的 CAD 应用。按真正决定成败的点对比——能不能动几何、跑在哪个宿主、许可能不能商用、出的是图纸还是网格。

精选 · 人工挑选

九个先看

不按 star 排序，只按「现在想动手，先装哪个」。数据排名在后面。

唯一重要的决策

你要 AI 真的去操作别人的 CAD 软件，还是让它自己写出可编辑的模型文件？

这和模型强弱无关——先定路线，再谈选型。走错路线，再好的 agent 也只能给你一堆没法交付的截图。

MCP 路线 能改几何

  • AI 直接调用宿主软件的 API/UI：改参数、装配、跑检查
  • 交付物是宿主原生文件（.FCStd / .SLDPRT / .kicad_pcb）
  • 适合：老模型要改、团队规范在某个软件里、电子 CAD
代价：依赖宿主软件版本与授权，桌面会话通常要开着；headless 支持参差

Code 路线 可复现

  • AI 写出 OpenSCAD / CadQuery / build123d 脚本，再编译成 STEP/STL
  • 交付物是源码 + 模型，天然可 diff、可参数化、可进 CI
  • 适合：新零件、参数化家族、3D 打印件、要复现的设计
代价：复杂曲面与装配表达力有限；设计师不一定会读代码
四步筛出候选
  1. 定路线：交付物必须在某个商业软件里被人接着改 → MCP 路线；否则 → Code 路线（往往更快、更可控）。
  2. 看宿主：FreeCAD / OpenSCAD / CadQuery / AutoCAD / SolidWorks / Fusion / Onshape / Inventor / SketchUp / KiCad / AEC，配方库里每个宿主都有现成接法。
  3. 对能力：要「导出 STEP / 出 DXF 图纸 / 渲染预览 / 干涉校验 / 直接打印」就点亮对应筛选；未提及 只代表文档没写，不等于不支持。
  4. 查许可：商用与闭源场景优先 MIT / Apache-2.0；GPL / AGPL 的先看协议再决定。

拿到手之后

怎么筛 · 怎么装 · 怎么在 Agent 里用

1MCP server 怎么接

  1. 克隆仓库、按 README 装依赖（多为 Python / Node）。
  2. 把 server 写进客户端的 mcp.json；本页每套配方都给了可复制的片段。
  3. 先在宿主软件里手动跑通一次，再让 Agent 上手——否则报错会被误判成模型笨。

2Skill 怎么装

  1. skill = 一个含 SKILL.md 的目录，放进 Agent 的 skills 目录（Claude Code 是 ~/.claude/skills/）。
  2. 认目录不认命令，无需改 mcp.json。
  3. 装完直接说需求 + 宿主 ID，Agent 会按 SKILL.md 执行。

3用自然语言点名

配方库里的「宿主 ID」不是命令行参数，是人话的一部分：

提示词模板
用 freecad-local 这套接法，打开我当前的 FreeCAD 文档，
把底板厚度从 3mm 改到 5mm，四个 M4 孔保持同心，
改完导出 STEP 和 STL 到 ./out/。先说明要调用哪些工具，等我确认。

4八条经验

  • 能锁定宿主版本就锁，桌面自动化对版本最敏感。
  • 让 Agent 先出参数表、再执行，返工成本低一个量级。
  • 几何正确性要外部校验（体积、包围盒、干涉），别信模型自述。
  • 同名仓库极多（openscad-mcp 有 5 个），认 star + 最近 push + 是否 headless。

诚实的局限

  • star 衡量关注度，不是质量；本页综合分是公开数据的计算结果，不是实测排名。
  • 能力矩阵读自各项目 README / description，未核读的项目只按描述归类，可能与实际不符。
  • 数据来自 GitHub Search API（未认证抓取，star 为快照）；项目会改名、归档、停止维护。
  • 本页没有逐个实跑任何 server：安装命令与片段是形态示例，以各仓库 README 为准。

维护 · 让数据不腐

它每周自己长一遍

这页的 star、最近 push、许可、是否归档，都来自 GitHub 检索，抄一次就开始过期。一条命令能跑完「检索 → 重建 → 差集报告 → 自检」，再镜像一个分支，线上就更新了——不用手抄表格，也不靠记忆。

1检索：先看谁还没收录

  1. build-data.mjs --fetch 重跑 9 条检索式，刷新 data/cache.json 里 156 个仓库的 star / 最近 push / 许可 / 归档标记。
  2. report.mjs 拿快照和图鉴做差集，列出检索到了但还没收录的候选（按 star 排）、已经归档的、超过 18 个月没 push 的；结果落在 data/candidates.json。
  3. 收不收由人定：新仓库补进 data/classification.json（形态 / 宿主 / 能力 / 一句话点评），再重建。脚本只负责把候选摆到桌面上。

2重建与自检

  1. build-data.mjs 重算综合分、重排 Top 6，并把结果内嵌回 index.html——页面断网也能打开。
  2. check.mjs 查 8 项一致性（数量、引用、评分区间、精选字段都对齐），smoke.mjs 在 Node 里把页面渲染一遍、点一遍。
  3. 两条都绿再提交。数据错一位，页面上所有结论都跟着错，而这页最容易错的就是数字。
一条命令跑完前三步
GITHUB_TOKEN=xxx ./scripts/refresh.sh     # 带 token 抓取，约 1 分钟
./scripts/refresh.sh --no-fetch          # 不联网，只用已提交的快照重建

3发布：main 是草稿，gh-pages 才是线上

每次 commit 之后
./scripts/deploy-pages.sh
# 等价于：git push origin refs/heads/main:refs/heads/gh-pages --force

Pages 的源是 gh-pages 分支根目录（项目页路径 /cad-skills-web/），推完 30–60 秒生效；仓库里放了 .nojekyll，免得下划线开头的文件被 Jekyll 吞掉。

这套流程的坑

  • 只推 main、忘了镜像 gh-pages：线上一个字都不会变，本地怎么刷新都是旧的——最常见的“我明明改了”。
  • 出口网络只放行 api.github.com 时，git push 会 SSL timeout / CONNECT 502；这种情况改用 Git Data API 提交，命令写在 README 里。
  • 每周自动跑：现成的工作流在 docs/ci/weekly-refresh.yml（每周一 03:00 UTC），要启用得把 token 的 Workflows 权限打开、文件搬进 .github/workflows/。
  • 未认证的搜索接口 10 次/分钟，9 条检索式约 3 分钟；带 token 30 次/分钟，且不会撞 403。
  • 精选、Top 6、宿主矩阵都由同一份 data/skills.json 计算：数据一改，三处一起变，不存在“某一处忘了同步”。

接入配方 · 宿主 ID

一条路线一套接法，复制就能用。

每套配方给三样东西：安装命令、客户端配置片段、提示词模板。
宿主 ID（如 freecad-local）写进提示词即可点名，Agent 会按该配方执行。
